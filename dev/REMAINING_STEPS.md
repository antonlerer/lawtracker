## 2. Развернуть сервис на сервере (A1, A2, A5, A7)

Что понадобится: сервер в России и домен. Примерно 1–2 часа.

1. **Сервер.** Облако с серверами в РФ (Selectel, Timeweb Cloud, Яндекс Облако, VK Cloud и т. д.). Подойдёт виртуальный сервер: 2 процессора, 4 ГБ памяти, 40 ГБ диска, Ubuntu 22.04 или 24.04. Запишите его IP-адрес.
2. **Домен.** Купите у регистратора (reg.ru, nic.ru и т. д.). В DNS домена создайте запись типа `A`: имя `@` (или поддомен, например `app`), значение — IP сервера. Ждите от 5 минут до пары часов.
3. **Подключитесь к серверу** (`ssh root@IP`) и установите Docker:
   ```bash
   apt update && apt install -y git ufw
   curl -fsSL https://get.docker.com | sh
   ufw allow 22 && ufw allow 80 && ufw allow 443 && ufw --force enable
   ```
4. **Скачайте проект:**
   ```bash
   cd /opt && git clone https://github.com/antonlerer/lawtracker.git && cd lawtracker
   git checkout claude/legal-analysis-platform-html-xrkbfv
   ```
   Репозиторий публичный: на сервер секреты в него не кладите, они лежат только в файле `.env` (его нет в репозитории и он в `.gitignore`).
5. **Настройте переменные:**
   ```bash
   cp deploy/env.example .env
   nano .env
   ```
   Заполните: `DOMAIN`, `BASE_URL` (с `https://`), `POSTGRES_PASSWORD` (`openssl rand -hex 24`), `ADMIN_TOKEN` (`openssl rand -hex 24`: 48 символов; это пароль от страницы `/admin`, сохраните в менеджере паролей), SMTP (раздел 4), при необходимости Telegram и GigaChat (разделы 7 и 9). `DEMO_MODE=false`, `COOKIE_SECURE=true`, `BETA_INVITE_ONLY=true`, `ENFORCE_PLAN_LIMITS=false` уже стоят по умолчанию.
6. **Запустите:**
   ```bash
   docker compose up -d --build
   docker compose ps                  # все сервисы Up; migrate завершился (Exited 0)
   docker compose exec app python -m app.cli check-config
   ```
   `check-config` печатает `ERROR` (бету запускать нельзя) и `WARN` (желательно исправить). Исправляйте в `.env` и применяйте командой `docker compose up -d`.
7. **Проверьте в браузере:** `https://ваш-домен` открывается с замком, `https://ваш-домен/api/healthz` отвечает `{"status":"ok"}`, `https://ваш-домен/admin` открывается и пускает по `ADMIN_TOKEN`.
8. **Демо-данных в базе быть не должно** (A7). На боевом сервере `seed` и `demo` заблокированы. Если вы запускали их раньше: `docker compose exec app python -m app.cli purge-demo`.

Если что-то не работает: `docker compose logs app --tail 100` (также `ingest`, `notify`, `caddy`). Если Caddy не получает сертификат: домен ещё не указывает на сервер или закрыт порт 80.

**Обновление версии:** `git pull && docker compose up -d --build`. Миграции применяются автоматически.

## 3. Поменять схему базы (для разработчика)

```bash
cd server
alembic revision --autogenerate -m "что изменилось"    # проверьте созданный файл в migrations/versions
alembic upgrade head
```
Тест `test_alembic_matches_models` падает, если вы изменили модель и забыли миграцию.

## 4. Почта: SMTP, SPF, DKIM, DMARC (C5)

Без этого письма (код подтверждения, сброс пароля, дайджест) не уходят или попадают в спам.

1. **Выберите почтовый сервис с SMTP** и подключите свой домен: Яндекс 360 для бизнеса, Mail.ru для бизнеса, Unisender Go, SendPulse, Mailganer и т. п. Для кода подтверждения и дайджестов лучше транзакционный сервис (Unisender Go и аналоги): он выдаёт SMTP-логин и пароль.
2. **Создайте ящики** `noreply@ваш-домен` (от кого шлём) и `support@ваш-домен` (поддержка).
3. **Добавьте записи в DNS домена** (сервис покажет точные значения; формат такой):
   - **SPF**, запись TXT на `@`: `v=spf1 include:_spf.<сервис> ~all`
   - **DKIM**, запись TXT на имя вроде `mail._domainkey`: длинное значение целиком копируется из панели сервиса
   - **DMARC**, запись TXT на `_dmarc`: `v=DMARC1; p=none; rua=mailto:support@ваш-домен` (для начала `p=none`, через месяц безопасных отправок можно `p=quarantine`)
4. **Впишите в `.env`:** `SMTP_HOST`, `SMTP_PORT` (обычно 587), `SMTP_USER`, `SMTP_PASSWORD`, `MAIL_FROM=LawTracker <noreply@ваш-домен>`, `SUPPORT_EMAIL=support@ваш-домен`. Перезапуск: `docker compose up -d`.
5. **Проверьте доставку:** зарегистрируйтесь на сайте с адресами Gmail, Яндекс, Mail.ru; убедитесь, что код приходит во «Входящие», а не в «Спам». Отправьте письмо на mail-tester.com (бесплатный тест оценивает настройки).
6. В письмах уже есть ссылка «Отключить или изменить уведомления», адрес поддержки и дисклеймер. Если сервис требует заголовок `List-Unsubscribe` для массовых рассылок, это маленькая доработка: скажите, добавлю.

## 5. Копии, алерты и мониторинг (A6, D5)

**Резервные копии.** На сервере:
```bash
mkdir -p /var/backups/lawtracker
crontab -e      # добавьте строку:
30 3 * * * cd /opt/lawtracker && deploy/backup.sh >> /var/log/lt-backup.log 2>&1
```
Хранятся 14 дней (`KEEP=14`). Копию стоит дублировать за пределы сервера (например, в облачное хранилище с `rclone`) и **один раз проверить восстановление**: `deploy/restore_check.sh /var/backups/lawtracker/lawtracker-<дата>.sql.gz` печатает число пользователей, компаний и изменений во временной базе.

**Алерты об ошибках сервера в Telegram.** Создайте бота (раздел 9) и узнайте свой `chat_id`: напишите боту любое сообщение, затем откройте `https://api.telegram.org/bot<ТОКЕН>/getUpdates` и найдите `"chat":{"id":число`. Впишите `ALERT_TELEGRAM_CHAT_ID=число` (и `BOT_TOKEN`). Сообщение приходит при необработанной ошибке, не чаще раза в 5 минут. Если нужен Sentry, скажите: подключается добавлением одной зависимости и переменной.

**Мониторинг доступности.** Либо бесплатный UptimeRobot / аналог: проверка `https://ваш-домен/api/healthz` раз в минуту с уведомлением в Telegram. Либо `deploy/healthcheck.sh` по cron на другом сервере или вашем компьютере (в начале файла пример строки cron).

## 6. Проверить загрузку реальных актов (B1)

1. На сервере: `docker compose exec app python -m app.cli ingest` печатает счётчики `seen / new / added / skipped / errors / analyzed / fallback`.
2. Если все `errors` или `seen: 0`: проверьте, что сервер открывает портал: `curl -I http://publication.pravo.gov.ru`. Если не открывается, нужен другой хостинг или прокси (в РФ обычно открывается).
3. Ожидаем: `added` > 0 при первом запуске (до 200 свежих актов), при повторном запуске `added: 0` (дублей нет).
4. Служба `ingest` затем работает сама раз в час (`INGEST_INTERVAL`). Ошибки видны в `docker compose logs ingest`.
5. Новые карточки появляются в `/admin` → «Очередь проверки» как «не проверено» и сразу видны клиентам с пометкой «Юристом не проверялось». Если хотите показывать клиентам только проверенные, скажите: это одна настройка.

## 7. Подключить ИИ-модель (B2)

1. Получите ключ GigaChat API на developers.sber.ru (кабинет GigaChat API, «Авторизационные данные» → ключ в формате Base64). Для личного/пилотного использования подходит `GIGACHAT_API_PERS`.
2. Впишите в `.env`: `GIGACHAT_AUTH_KEY=...`, `GIGACHAT_SCOPE=GIGACHAT_API_PERS`. **Ключ нельзя присылать в чат и коммитить.**
3. Если при запуске ошибка сертификата: скачайте корневой сертификат НУЦ Минцифры (инструкция в документации GigaChat, раздел про сертификаты), положите файл в `deploy/certs/` (имя, например, `russian_trusted_root_ca.pem`), добавьте в `.env`: `GIGACHAT_CA_BUNDLE=/srv/certs/russian_trusted_root_ca.pem` и пересоберите: `docker compose up -d --build`. **Проверку TLS отключать нельзя**: `check-config` считает это ошибкой.
4. **Прогон на реальных актах:** возьмите 10–20 актов с pravo.gov.ru, текст каждого сохраните в файл и запустите
   ```bash
   docker compose exec app python -m app.cli analyze --file /tmp/act.txt --title "Название акта" --type "Федеральный закон" --published 2026-10-01
   ```
   Смотрите на `report` (проверка цитат, дат и чисел кодом) и `notes`. По результатам правится промпт `server/ingest/prompts.py`: это работа разработчика или моя, пришлите вывод.
5. Лимиты и стоимость: в бете хватает бесплатных токенов GigaChat; следите за расходом в кабинете GigaChat.

## 8. Эталонная выборка, стартовые карточки, правила (B3, F1, F2)

**Эталонная выборка (для замера качества и заявления TRL 5):**
1. Отдайте юристу файл `server/eval/gold_template.xlsx` (инструкция на первом листе). Юрист заполняет 30–100 реальных актов: текст акта, значимость, тематика, влияние, дата вступления в силу и пары «акт × типовая компания».
2. Конвертируйте: `python -m ingest.gold_xlsx convert gold.xlsx gold.jsonl` (ошибки в файле скрипт перечислит по строкам).
3. Замер: `docker compose exec app python -m app.cli evaluate --gold /tmp/gold.jsonl` печатает точность по тематике, влиянию, датам, применимости и проверке цитат.

**Стартовые карточки (F1: нужно 30–50 проверенных к запуску):**
1. После первого `ingest` откройте `/admin` → «Очередь проверки».
2. Юрист открывает карточку: сверяет цитату и дату с первоисточником, при необходимости правит текст и действия, ставит «Сохранить и опубликовать как проверенное» (или «Скрыть», если акт не нужен малому бизнесу).
3. Цель: по каждой приоритетной теме 3–4 проверенные карточки. Правила применимости (`requires`, `reasons`) редактируются там же в формате JSON; сервер сам отклоняет неверные поля и операции.
4. **Для F2:** юрист создаёт в приложении 5–10 тестовых компаний (разных отраслей и размеров) и смотрит, какие карточки им показываются и почему («Почему это показано вам»). Спорные случаи правятся в правилах.

## 9. Telegram-бот (C4)

1. В Telegram найдите `@BotFather` → `/newbot` → задайте имя и username (должен оканчиваться на `bot`). Получите токен: **это секрет**.
2. Впишите в `.env`: `BOT_TOKEN=...`, `TELEGRAM_BOT_USERNAME=<username без @>`, `TELEGRAM_WEBHOOK_SECRET=<openssl rand -hex 16>`. `docker compose up -d`.
3. Зарегистрируйте webhook (один раз; подставьте свои значения):
   ```bash
   curl "https://api.telegram.org/bot<ТОКЕН>/setWebhook?url=https://<ДОМЕН>/api/telegram/webhook/<TELEGRAM_WEBHOOK_SECRET>"
   curl "https://api.telegram.org/bot<ТОКЕН>/getWebhookInfo"      # ожидаем url и pending_update_count 0
   ```
4. Проверка: в кабинете «Telegram» → получить код → отправьте код боту → статус «подключено» → «Отправить тестовое сообщение».
5. Если бот пока не нужен, оставьте `BOT_TOKEN` пустым; тогда интерфейс на сайте стоит оставить, но не обещать его в бете (или скажите, скрою раздел).

## 10. Юридические тексты и согласия (C6)

1. Юрист присылает тексты политики конфиденциальности, пользовательского соглашения и согласия на обработку ПД (ТЗ: `legal/TZ_yurist.docx`).
2. Тексты заменяют заглушки на страницах `#/privacy` и `#/terms` в `index.html` (функция `viewLegal`): отдайте тексты мне, внесу.
3. После утверждения поменяйте `TERMS_VERSION` в `.env` (например, `2026-12-01`). Версия сохраняется для каждого пользователя в журнале согласий (`consent_records`) вместе с датой и IP; `check-config` предупреждает, пока версия помечена `draft`.
4. Если выберете оператора ПД и надо уведомить Роскомнадзор (152-ФЗ), это делает компания-оператор через Госуслуги; как вопрос к юристу: `legal/TZ_yurist.md`.
5. Проверьте на живой базе: «Скачать мои данные» (аккаунт) и «Удалить аккаунт» (стирает пользователя, его отметки, сессии и, если он владелец и один, компанию).

## 11. Что осталось доделать в коде (скажите, и я сделаю)

- Подсчёт кликов из писем (метрика «клик из письма»): нужны отслеживаемые ссылки в дайджесте.
- Переключатель «показывать профиль команде»: непонятно, что именно он должен делать.
- `List-Unsubscribe` в письмах-дайджестах (если сервис потребует).
- Показ клиентам только проверенных юристом карточек (настройка).
- Sentry вместо/вместе с Telegram-алертами.
- Платежи (не нужны для беты).

## 12. Лимиты и защита (D2, D3)

- В приложении уже работают троттлинг входа и кодов, защита от CSRF, заголовки безопасности (в том числе HSTS при `COOKIE_SECURE=true`).
- Ограничение размера запроса стоит в Caddy (1 МБ). Ограничение частоты запросов на уровне прокси: если появятся злоупотребления, добавляется модуль rate-limit для Caddy или закрытие `/admin` по IP (пример закомментирован в `deploy/Caddyfile`).
- Ручной чек-лист проверки перед запуском: `dev/SECURITY_CHECKLIST.md`.

## 13. Порядок действий до запуска беты

1. Сервер и домен → раздел 2 (`check-config` без `ERROR`).
2. SMTP → раздел 4; Telegram по желанию → раздел 9.
3. Ключ GigaChat → раздел 7; `ingest` на реальном портале → раздел 6.
4. Юрист: тексты (раздел 10), очередь проверки и стартовые карточки (раздел 8).
5. Копии и мониторинг → раздел 5.
6. Пилот на 5 компаниях: выдать коды в `/admin` → «Приглашения», через неделю посмотреть «Метрики» и «Обратная связь».
7. Запуск: открыть набор 30–50 компаний, принимая заявки со страницы `#/beta` («Заявки» в `/admin` → «Пригласить и отправить код»).

Цели беты, которые считает `/admin`: активных компаний ≥ 30 на 4-й неделе, средняя оценка ≥ 4, нерелевантных менее 20 %.
