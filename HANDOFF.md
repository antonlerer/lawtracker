## 2. Что сделано по порядку

1. **Оценки ИИ.** Как часто ошибается GigaChat; сравнение моделей (ChatGPT, GigaChat и др.), стоимость, сложность подключения. Вывод: для бета-версии подходит GigaChat на бесплатных токенах, с проверкой результата программой и юристом.
2. **Презентация (17 слайдов).** Варианты слайдов «Решение: суть» (4 варианта) и «Проблема» (3 варианта с цифрами), итоговые `.pptx` и `.pdf`, замена QR-кодов на слайде «Приложения» (Яндекс.Диск и GitHub). Слайды публиковались как артефакт (ссылка в разделе 8).
3. **Экономика.** `lawtracker-economics.xlsx` переделан: минимальный сценарий = бета (ежемесячно только хостинг 300 ₽ и рассылки 770 ₽, ИИ на бесплатных токенах GigaChat, без зарплат), реалистичный = команда с зарплатами. Формулы живые. Пересчёт в LibreOffice зависал, значения считались отдельно на Python.
4. **Сайт.** `index.html` — одностраничное приложение. Предложены три варианта дизайна, выбран и доработан «сигнатурный» стиль (знак § с закладкой, маркер, отрывные листки со сроком, шрифты Literata и Golos Text).
5. **Чужой репозиторий lwtk** (код одноклассника-участника) изучен, оценён TRL (платформа 4, ИИ-ядро 3).
6. **Серверная часть** (`server/`): написана заново, с профилем компании вместо тегов (27 полей), правилами применимости (JSON-деревья над 21 полем), лентами, действиями, уведомлениями, Telegram, командой с ролями, тарифами, демо-режимом. 97 тестов, затем 137.
7. **Подключение сайта к серверу** (режим LIVE). Один и тот же `index.html` работает с сервером и без него (демо в localStorage). Сквозной тест в браузере `server/e2e/live_site.js` — 26 шагов. Снято видео работы сервиса.
8. **ИИ-разбор актов** (`server/ingest/`): промпт (`prompts.py`), проверки кодом (`analyze.py`), клиенты моделей (`llm.py`), загрузка PDF (`text.py`), оценка качества (`evaluate.py`), CLI-команды `analyze` и `evaluate`, админ-метод `POST /api/admin/changes/{id}/analyze`.
9. **Документы:** документация бэкенда, `PROJECT_CONTEXT.md`, ТЗ юристу (`legal/`), заполнены пустые пункты паспорта проекта и разделы VI–VII паспорта команды (`passports/`), описание для сайта акселератора (`accelerator/`).
10. **Ответы на вопросы:** рынки НТИ, сквозные технологии, готовность к хостингу, работа ИИ-обработки, TRL, как посмотреть сайт, как безопасно передать ключ ИИ.

## 3. Ключевые решения и почему

| Решение | Причина |
|---|---|
| Профиль компании (типизированные поля), а не теги | Требование пользователя; точнее, проверяемо, даёт объяснение «почему это вам» |
| Правила применимости как JSON-дерево, без `eval` | Безопасность, возможность проверять правила, которые пишет ИИ |
| «Модель предлагает — код проверяет» | ИИ ошибается; цитаты, даты и числа проверяются программой, результат помечается «не проверено юристом» |
| Даты считает программа | Модели часто ошибаются в арифметике дат |
| Рабочие дни не считаются, срок остаётся пустым | Нельзя считать вслепую без производственного календаря |
| Один `index.html` без сборки, два режима (LIVE и демо) | Сайт должен работать на GitHub Pages и как открытый файл |
| Сервер отдаёт сайт сам | Нет CORS и сторонних cookie, проще защита |
| Серверные сессии с хешем токена, CSRF-проверка, троттлинг | Базовая безопасность без внешних зависимостей |
| Поиск по изменениям в Python | SQLite не умеет `lower()`/`LIKE` для кириллицы |
| Тарифы 0 / 690 / 1 690 / от 4 900 ₽ | Предварительные, ориентир — КонсультантПлюс около 3 500 ₽/мес |
| ИИ не получает персональные данные клиентов | В запрос идёт только текст публичного акта (важно для 152-ФЗ) |
| Платежей нет | Смена тарифа — заявка, применяется вручную; в `DEMO_MODE` владелец меняет тариф сам |

## 4. Текущее состояние (на дату файла)

- **Работает (проверено тестами на подставных данных):** регистрация и вход, профиль по 10 шагам, правила применимости, ленты с фильтрами, действия со статусами, уведомления и расписание рассылки, привязка Telegram (через подставной клиент), команда и роли, тарифы, аккаунт, поддержка, админ-методы, ИИ-разбор на подставной модели. 137 тестов, сквозной тест 26 шагов.
- **TRL:** платформа 4; ИИ-ядро 3–4.
- **Не проверено вообще:** реальный pravo.gov.ru, живая модель (GigaChat и др.), качество промпта на реальных актах, извлечение кириллицы из PDF портала, SMTP, Bot API Telegram, PostgreSQL.
- **Репозиторий публичный:** в нём лежат паспорта и экономическая модель — решить, закрывать ли (см. `legal/TZ_yurist.md`, п. 4.5).

## 5. Что осталось сделать (по приоритету)

1. **Ключ ИИ и сеть.** Пользователь добавляет `GIGACHAT_AUTH_KEY` в секреты окружения (не в чат!) и разрешает хосты `ngw.devices.sberbank.ru`, `gigachat.devices.sberbank.ru`, `pravo.gov.ru`, `publication.pravo.gov.ru`. Затем запустить `python -m app.cli analyze ...` на реальных актах.
2. **Эталонная выборка.** 50–100 актов, размеченных юристом (формат `server/eval/gold_example.jsonl`), замер точности командой `evaluate`. Без этого TRL 5 не заявить.
3. **Юрист.** Выдать `legal/TZ_yurist.docx`; получить тексты политики, соглашения, согласия на обработку ПД (на сайте `#/privacy` и `#/terms` — черновики).
4. **Развёртывание.** Docker, HTTPS-прокси, хостинг в РФ, миграции (Alembic), резервные копии, мониторинг. `DEMO_MODE` в продакшене выключить.
5. **Telegram-бот.** Реальный токен и webhook (код есть, не проверен на живом Bot API).
6. **Почта.** Настроить SMTP.
7. **Слайды.** Обновить «Технологическое ядро», «Уровень готовности» и, возможно, «Бизнес-модель» под текущее состояние кода и экономики, пересобрать `.pdf` и `.pptx`.
8. **Фронтенд, недоделки:** скрытие кнопок по ролям, смена e-mail, переключатель «показывать профиль команде».
9. **Паспорт проекта:** пункт 17 заявляет PostgreSQL+pgvector и Airflow — в коде их нет; переписать как «планируется».
10. **НТИ.** В паспортах указаны EduNet, SafeNet, TechNet; в `PROJECT_CONTEXT.md` до сих пор стоит Нейронет — выровнять после решения наставника.
11. **Прочее:** рабочие дни в расчёте сроков, полнотекстовый поиск при росте каталога, упрощение запасного пути `ingest/enrich.py`.

## 6. Известные особенности и ловушки (для разработчика и ИИ)

- Отсутствующее поле профиля даёт `False` в любой операции правил, включая `ne` и `is_false`.
- Индекс действия — часть ключа `action_states`; при перезаписи `changes.actions` порядок нельзя менять без пересмотра состояний.
- `evaluate(ch, v)` в `app/changes.py` не персонализирует, пока нет сохранённых шагов профиля или тариф `free`.
- Админ-методы отключены (404), пока не задан `ADMIN_TOKEN`; в `DEMO_MODE` код подтверждения возвращается в ответе как `dev_code`.
- Старые правила с подстроками давали ложные срабатывания («ии» в «Федерации»); в `ingest/enrich.py` стемы по началу слова.
- Первичная регистрация в демо: `demo@example.org` / `DemoPassw0rd1` (создаётся `python -m app.cli demo`).
- Тесты запускаются командой `pytest` из `server/` (нужен `requirements-dev.txt`).
- `README.md` в `server/` и `docs/BACKEND.md` описывают запуск и API; не дублировать, а обновлять оба при изменениях.

## 7. Особенности среды разработки (облачный контейнер)

- Нет доступа к pravo.gov.ru, GigaChat, SMTP, Telegram Bot API; интеграции проверялись на подставных клиентах.
- Python в контейнере двойной (3.11 и 3.13); пакеты бывают в другой версии, чем `python3`. Для `python-docx` использовался `python3.13`.
- Не завершайте процессы паттерном `pkill -f`, который содержится в вашей же команде (убивает оболочку); пользуйтесь pid-файлами.
- Удаление относительных `rm -f dir/*` блокируется проверкой безопасности; пишите в новые каталоги.
- Ключи и токены никогда не вставляйте в чат; только через настройки окружения.

## 10. Как продолжить в новом чате

Вставьте в начало: `PROJECT_CONTEXT.md` + `HANDOFF.md`; при технической задаче добавьте `server/docs/BACKEND.md`. Затем напишите задачу, например:

> «Продолжаем проект LawTracker по файлам выше. Задача: …»

Правила для ИИ: не выдумывать факты о законах и сроках; не заменять профиль тегами; любые правила применимости пропускать через `rules.validate_rule`; сохранять работу сайта без сервера; не просить и не принимать ключи в чате; честно писать, что не проверено.
