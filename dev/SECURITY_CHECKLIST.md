# Чек-лист безопасности перед запуском беты (D2, D3)

Версия от 20.11.2026. Часть пунктов проверяется автоматически (тесты), часть нужно пройти руками на боевом адресе.

## Проверено автотестами (`server/tests`)

- [x] Нельзя получить чужие данные компании: все запросы привязаны к компании пользователя через членство, не через параметры.
- [x] Роли: наблюдатель и участник не могут менять профиль, команду, тариф (проверка на сервере, не только в интерфейсе).
- [x] Методы `/api/admin/*` и страница `/admin` без верного токена отвечают 404, не подсказывая, что они есть.
- [x] CSRF: изменяющий запрос без JSON или `X-Requested-With` отклоняется.
- [x] Перебор пароля, кода подтверждения, сброса пароля и формы заявок ограничивается (429).
- [x] Пароли хранятся хешем (scrypt), токены сессий и кодов — SHA-256, код приглашения одноразовый.
- [x] Правила применимости не исполняют код (`eval` нет), неверные поля отклоняются.
- [x] Заголовки: `nosniff`, `X-Frame-Options: DENY`, HSTS при `COOKIE_SECURE=true`.
- [x] Выгрузка данных отдаёт только данные самого пользователя; CSV для аналитика без e-mail и защищён от формул Excel.
- [x] Необработанная ошибка не раскрывает деталей и отправляет алерт.

## Пройти руками на боевом сервере

1. `docker compose exec app python -m app.cli check-config` — нет `ERROR`.
2. Откройте сайт по `http://` — переходит на `https://`; в браузере замок без предупреждений.
3. В DevTools → Application → Cookies: `lt_session` помечена `HttpOnly` и `Secure`.
4. Откройте `https://домен/api/docs`: решите, нужна ли публичная документация API (при необходимости закройте в Caddy).
5. `https://домен/admin` открывается, но без токена данных не показывает; неверный токен — сообщение об ошибке.
6. Два тестовых аккаунта в разных компаниях: из аккаунта A подставьте в адрес карточки/действия идентификаторы из аккаунта B (`/api/changes/…`, `/api/team/<id чужого участника>`) — чужие данные не приходят, действия отклоняются.
7. Введите 10 неверных паролей подряд — на 9-й попытке ответ 429 «Слишком много попыток».
8. Посмотрите логи (`docker compose logs app`): нет паролей, токенов, полных кодов подтверждения, ключей.
9. В репозитории нет секретов: `git log -p | grep -iE "ADMIN_TOKEN=|BOT_TOKEN=|AUTH_KEY=|PASSWORD="` не находит боевых значений; `.env` в `.gitignore`.
10. Порты наружу: только 22, 80, 443 (`ufw status`); PostgreSQL снаружи недоступен (в compose порт не публикуется).
11. Резервная копия восстанавливается (`deploy/restore_check.sh`), копия лежит не только на том же сервере.
12. Удаление аккаунта и выгрузка данных работают на боевой базе (раздел 10 в `REMAINING_STEPS.md`).
13. Сменить `ADMIN_TOKEN`, если он когда-либо попал в чат, письмо или скриншот.
14. Если появятся злоупотребления: ограничение частоты на прокси (модуль rate-limit для Caddy) или закрытие `/admin` по IP (пример в `deploy/Caddyfile`).
