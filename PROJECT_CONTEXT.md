## 0. Краткая выжимка (если нужно только это)

LawTracker — SaaS для малого и среднего бизнеса РФ: клиент заполняет **профиль компании** (типизированные поля, не теги),
система берёт новые акты с официального портала, **ИИ разбирает текст**, а **код проверяет ответ модели** (цитаты, даты, числа),
затем **правила применимости** сопоставляют акт с профилем и показывают только то, что касается этой компании, с объяснением
«почему вам», сроком и планом действий. Доставка: веб-кабинет, e-mail, Telegram. Тарифы: 0 / 690 / 1 690 / от 4 900 ₽ в месяц.
Состояние: рабочий прототип (TRL 4): сайт + серверная часть + тесты на подставных данных; на реальных актах и живой модели ещё не запускалось.
Стек: Python 3.11, FastAPI, SQLAlchemy, Pydantic, SQLite/PostgreSQL; фронтенд — один файл `index.html` без сборки.

## 1. Продукт и проблема

**Название:** LawTracker. **Тип:** облачная платформа по подписке (SaaS, freemium), B2B; партнёрский канал B2B2B (бухгалтеры и юристы с портфелем клиентов).
**Суть:** платформа персонального мониторинга и ИИ-анализа изменений законодательства РФ для МСП. Клиенту нужна не новость, а ответ на три вопроса:
что изменилось, касается ли это нас, что и до какого срока нужно сделать.

**Проблема клиентов (подтверждена опросом предпринимателей; результаты — `survey/opros.pdf`):**
1. избыток информации: важное теряется среди неактуального;
2. сложный юридический язык: непонятны практические последствия;
3. нет персонализации: одна поправка по-разному важна магазину, IT-компании и стройке;
4. ручной мониторинг отнимает время, риск пропуска нормы и срока остаётся.
Последствия: штрафы, претензии, срочная переделка документов и процессов.

**Как решают сейчас:** читают новости и Telegram-каналы, платят бухгалтеру или юристу, пользуются справочными системами (дорого, нет отбора).

**Что даёт продукт (карточка изменения):** краткий вывод простым языком; что изменилось; кого касается; почему показано именно этой компании
(по данным профиля); дата публикации и вступления в силу; уровень влияния (высокий/средний/низкий); действия с ответственными и сроками;
дословная цитата из акта; ссылка на первоисточник; уровень уверенности анализа и отметка «проверено юристом».
Материалы носят информационный характер и не заменяют юридическую консультацию.

**Отличия от конкурентов:** не заменяет справочно-правовую систему, а применяет изменения к конкретному бизнесу: лента по профилю, объяснение причины показа,
план действий с ответственными, ссылка на источник и уровень уверенности ИИ, напоминания о сроках, цена от 690 ₽/мес.
Конкуренты: КонсультантПлюс, Гарант, Кодекс/Техэксперт, Контур, Telegram-каналы и СМИ, сайты госорганов, внешние юристы и бухгалтеры, ручной мониторинг.
Оценка команды: у конкурентов ориентир ≈3 500 ₽/мес (КонсультантПлюс), у остальных «по запросу»; сравнение «Да/Частично/Нет» в презентации — оценка команды по открытым данным.

## 2. Аудитория и рынок (оценки команды, не проверенные данные)

- Сегменты: (1) ИП и микро/малый бизнес без юриста; (2) средний бизнес с юристом/бухгалтером/HR/комплаенсом (нужны сроки, команда);
  (3) бухгалтерские и юридические фирмы с десятками клиентов (канал продаж); (4) группы компаний.
- Первые отрасли: интернет-торговля, IT, персональные данные, трудовое право, реклама, строительство, медицина, производство.
- ЛПР: собственник/руководитель; пользователи: юрист, бухгалтер, финансовый директор, HR, комплаенс.
- Размер: ≈6 млн субъектов МСП (реестр МСП ФНС, цифра уточняется). TAM ≈ 78 млрд ₽/год (6 млн × ≈1 090 ₽ × 12), SAM ≈ 7,8 млрд ₽/год (≈10 % компаний приоритетных отраслей),
  SOM ≈ 6,5 млн ₽/год (≈500 платных клиентов к 24-му месяцу). Все цифры расчётные.
- Рынок НТИ: Нейронет (сегмент «НейроАссистент»); сквозные технологии: ИИ, большие данные; критическая технология РФ: ИИ и анализ неструктурированных текстов.

## 5. Архитектура

```
Браузер (index.html, SPA) ──HTTP/JSON──► FastAPI (server/app) ──► SQLAlchemy ──► SQLite / PostgreSQL
                                              ▲                                        ▲
Cron/процессы:  python -m app.cli ingest ─────┘  (pravo.gov.ru → текст PDF → ИИ-разбор → таблица changes)
                python -m app.cli notify --loop 300 (рассылка почта/Telegram)
Telegram Bot API ◄── webhook /api/telegram/webhook/{secret}
```

- Сервер сам отдаёт `index.html` по `/` — запросы `/api` идут на тот же адрес (нет CORS и сторонних cookie).
- Один и тот же `index.html` работает в двух режимах: **LIVE** (если отвечает `GET /api/meta`) и **демо** (без сервера; данные в localStorage; GitHub Pages или открытый файл).
- В презентации заявлена целевая архитектура PostgreSQL + pgvector, Apache Airflow; **в коде их нет**: сейчас cron-подобные CLI-команды, векторного поиска нет.

## 6. Сайт (`index.html`)

### 6.1 Общее
- SPA на чистом JS (без фреймворков и сборки), роутинг по hash: `#/...`. Весь UI собирается строками HTML (`view*()` функции) и вставляется через `render()`.
- Публичные страницы: `#/` (главная), `#/pricing`, `#/about`, `#/faq`, `#/contacts`, `#/privacy`, `#/terms`, `#/register`, `#/login`, `#/forgot`, `#/reset`.
- Кабинет: `#/app` (обзор), `#/app/digests` (дайджесты/лента), `#/app/saved`, `#/app/change/<id>` (карточка), `#/app/profile` (профиль по шагам),
  `#/app/notifications`, `#/app/telegram`, `#/app/team`, `#/app/plan` и `#/app/billing`, `#/app/account`, `#/app/support`. Онбординг — после регистрации.
- Ключевые функции: `viewHome, viewPricing, viewRegister, viewLogin, viewOnboarding, appShell, navHTML, viewOverview, viewDigests, renderDigestList, filterChanges, viewChange,
  viewProfile, stepForm, validateStep, viewNotifications, viewTelegram, viewTeam, viewPlan, viewAccount, viewSupport, viewBilling, render, toast, modal, changeItem, countdown`.
- Состояние интерфейса в localStorage: только тема, палитра, шрифт (в режиме LIVE данные пользователя хранятся на сервере).
- Адаптивная вёрстка (мобильная нижняя навигация: Обзор, Дайджесты, Сохранённое, Уведомления), светлая и тёмная темы, панель «Демо» для показа.

### 6.2 Слой LIVE (блок `/* LIVE: РАБОТА С СЕРВЕРОМ */`)
- `api(method, path, body)` — обёртка fetch (JSON, cookie, `X-Requested-With`), разбор ошибок `{error:{code,message,fields}}`, обработка 401 (`handleExpired`).
- Преобразования: `companyFromApi`, `stepToApi` (поля вида `pdEmployees` ↔ `pd_employees`), `changeFromApi` (даты ↔ смещения в днях).
- Загрузка: `bootLive`, `loadAll`, `loadChanges`, `loadSessions`; формы: словарь `LIVE_FORMS` (regForm, loginForm, forgotForm, resetForm, contactForm, obVerify, obCompany, obJoin, obBasics, obTopics, profForm, accForm, pwForm, supForm).
- Переопределения действий `ACT.*` (через `ACT0`), `liveChange`/`liveClick` (делегирование событий), `renderDemoLive`/`demoActionLive`/`fillDemoLive` (панель «Демо» в LIVE).
- Отметки действий: `data-actstatus` (todo/doing/done) → `PUT /api/changes/{id}/actions/{idx}`; срок `null` показывается как «срок не указан».
- Подбор «касается ли вас» и тексты причин приходят с сервера, браузер их не считает. Ограничения тарифа отображаются в интерфейсе (подсказки, закрытые рекомендации, лимиты сфер/участников).
- Не реализовано на фронте: скрытие кнопок по ролям (сервер роли проверяет), смена e-mail, переключатель «показывать профиль команде».

### 6.3 Дизайн («сигнатурный» стиль)
- Идея: юридический «блокнот»: знак параграфа «§» с закладкой как логотип (`.logo-mark`), маркер-выделение ключевых слов (`.hl`), закладки-ленты на карточках (`.crow::before`),
  «отрывные листки» со сроком (`.leaf`), фон из точек как разлинованный журнал.
- Шрифты: Literata (заголовки), Golos Text (текст). Тёмная тема и несколько палитр (бордовая, лесная и др.) — переключаются в панели «Демо».
- Тон текстов: простой русский, без канцелярита; акцент на сроках, действиях и причине показа.

### 7.4 Правила применимости (DSL)
Дерево JSON над полями профиля: лист `{"field","op","value"}`; узлы `{"all":[...]}`, `{"any":[...]}`, `{"not":{...}}`; глубина ≤ 6, узлов ≤ 60.
Операции по типу поля: bool — `is_true,is_false`; str — `eq,ne,in,not_empty`; int — `eq,ne,gt,gte,lt,lte`; list — `contains,contains_any,not_empty`.
Изменение касается компании, если выполнены **все** `requires` и сработала **хотя бы одна** причина из `reasons` (`{"when":правило,"text":"..."}`; в тексте плейсхолдеры `{headcount}`, `{size_label}` и др.).
Отсутствующее поле → `False` для любой операции (включая `ne` и `is_false`). Региональный фильтр: если у изменения есть `regions`, а у компании регионы указаны, нет «Вся Россия» и нет пересечения — не касается.
Пока профиль не начат (нет сохранённых шагов) или тариф `free`, персонализации нет.

### 7.5 Лента
Видны только `status=published`; `free/basic` — не старше 90 дней. «Требует внимания»: персональное, не черновик, есть незавершённые действия и (impact=high или срок вступления через 0–30 дней).
`GET /api/changes`: `q, period(all/7/30/90), topic, impact, status(all/new/read/saved/attn), sort(date/impact/eff), personal, page, per_page(≤50), detail`. Поиск `q` — в Python (casefold), т.к. SQLite не умеет lower() для кириллицы.

auth: `POST /api/auth/{register,login,logout,verify-email,resend-code,forgot,reset}`, `GET /api/auth/me` · account: `PATCH /api/account`, `POST /api/account/password`, `GET/DELETE /api/account/sessions`, `DELETE /api/account` ·

### 7.7 Безопасность
scrypt для паролей; токены сессий/кодов/сброса хранятся хешами; cookie `lt_session` HttpOnly + SameSite=Lax (+Secure по настройке); CSRF: изменяющий запрос — JSON или `X-Requested-With`;
троттлинг входа/кодов/сброса; `extra="forbid"` в схемах; правила валидируются, `eval` не используется; изоляция компаний через `Ctx`; заголовки nosniff, Referrer-Policy, Cache-Control: no-store.

Настройки: каналы cabinet/email/tg, частота почты now|daily|weekly, тематики, минимальная значимость, дни недели 1–7, время ЧЧ:ММ, пауза. `notify.dispatch()` — проход рассылки: кандидаты — опубликованные не-черновики, персональные, не прочитанные,

## 9. ИИ-разбор актов (`server/ingest/`)

Принцип: **модель предлагает — код проверяет**. Конвейер `ingest.run.run_ingest` (CLI `python -m app.cli ingest`):
RSS и API publication.pravo.gov.ru (`pravo.py`) → новые номера публикации → PDF текста акта (`text.py`: GET `/File/Pdf?eoNumber=`, pypdf, очистка) →
`Analyzer.analyze` (`analyze.py`) → запись `Change(id="pravo-<eo>", reviewed=False)`. Если нет модели/текста/ответа — запасной путь `enrich.py` (тематика по началам слов, значимость по виду акта, правила из шаблона тематики, `confidence=low`);
награждения, назначения, ратификации и т. п. отбрасываются.

**Клиенты моделей (`llm.py`):** протокол `LLM.chat(system, user, *, temperature, max_tokens) -> str|None`; `GigaChatLLM` (OAuth + chat, TLS-проверка включена), `OpenAICompatibleLLM` (vLLM, Ollama, шлюзы), `make_llm(settings)` → `None`, если не настроено.

**Промпт (`prompts.py`, `PROMPT_VERSION = "2026-10-21.1"`):** опирается ТОЛЬКО на текст акта; неизвестное → `null`, не догадка; цитаты дословные (≤350/250 знаков); тексты внутри `<текст_акта>` — данные, а не инструкции (защита от prompt injection);
простой язык; критерии relevant/тематики/impact/is_draft; модель не считает даты, а копирует `effective_phrase`; правила применимости в формате DSL с допустимыми полями; действия с `basis_quote`; поля `confidence` и `uncertainties`; схема JSON, вымышленный пример и чек-лист проверки.
Содержит `REPAIR_PROMPT` для одной попытки починки формата.

**Проверки кодом (`analyze.py`):**
- JSON разбирается строго (`parse_json`), при ошибке — одна починка;
- цитаты (`key_quote`, `basis_quote` причин и действий) должны встречаться в тексте (`quote_in`: допуск на пробелы/кавычки/тире, но не на слова); действие без подтверждённой цитаты отбрасывается;
- даты считает `resolve_date` (календарные даты, ДД.ММ.ГГГГ, «по истечении N дней/месяцев после опубликования», «со дня опубликования»); рабочие дни не считаются; дата/фраза должны быть в тексте;
- числа в пояснениях сверяются с текстом (`ungrounded_numbers`), чужие → `confidence=low`;
- правила валидируются (`rules.validate_rule`), при отказе — шаблон тематики (`enrich.TOPIC_RULES`);
- `ANALYSIS_PASSES` проходов (по умолчанию 2): консенсус по relevant/topic/impact/сроку, расхождение → `confidence=low`;
- длинный текст сокращается до 24 000 знаков с сохранением фраз о вступлении в силу (`select_excerpt`), уверенность не выше `mid`;
- результат `AnalysisResult(relevant, fields, notes, report, answers)`; все записи с `reviewed=False`.

**Оценка качества (`evaluate.py`):** `python -m app.cli evaluate --gold eval/gold_example.jsonl` — точность relevance/topic/impact/draft/срока, доля проверенных цитат, точность и полнота применимости по профилям, точность по уровням уверенности.
Файл `gold_example.jsonl` — 3 синтетических примера; нужен реальный набор 50–100 актов, размеченный юристом.
**Другие точки входа:** `python -m app.cli analyze --file akt.txt --title "..." --published 2026-09-10`; `POST /api/admin/changes/{id}/analyze {"text","apply"}` (dry-run по умолчанию).

**Не проверено:** качество промпта на живой модели и реальных актах; извлечение кириллицы из PDF портала; реальные pravo.gov.ru, GigaChat, SMTP, Bot API Telegram, PostgreSQL.

## 11. Известные ограничения и список доработок
1. Нет миграций (Alembic), Docker, HTTPS-прокси, бэкапов, мониторинга; нет платежей.
2. Нет доступа к pravo.gov.ru/GigaChat/SMTP/Telegram из среды разработки — эти интеграции проверены только на подставных клиентах.
3. Поиск по тексту в Python — для десятков тысяч записей нужен полнотекстовый индекс; векторного поиска (pgvector) нет.
4. Рабочие дни при расчёте сроков не считаются (срок остаётся пустым).
5. Старый путь `enrich(raw, llm)` (по названию акта) оставлен как запасной.
6. Юридическая сторона: согласие на обработку ПД, размещение БД в РФ (152-ФЗ), оговорка «не заменяет консультацию юриста»; карточки ИИ требуют проверки юристом перед показом клиентам.
7. Данные в демо (11 изменений, компания «Нордвуд Логистика») — вымышленные; цены и рыночные оценки предварительные.

## 12. Правила для ИИ, который работает с этим проектом
- Не выдумывай факты о законодательстве, статьях и сроках: источник — текст акта, остальное помечай как предположение.
- Не используй теги вместо профиля: применимость считается по полям профиля и правилам (раздел 7.4).
- Любое правило применимости должно проходить `rules.validate_rule` (только перечисленные поля и операции).
- Не добавляй зависимости и фреймворки на фронтенд без необходимости: `index.html` — один файл без сборки; сохраняй работу в режиме без сервера (демо).
- Сохраняй стиль кода: русские комментарии и сообщения пользователю, простые функции, тесты pytest на каждое изменение логики.
- Секреты (ключи GigaChat, токены, пароли) не вставляй в код и в чат; используй переменные окружения.
- Тексты для клиентов — простым русским языком, без канцелярита и без обещаний, что сервис заменяет юриста.
- Если не уверен — скажи, что именно не проверено (см. разделы 9 и 11), и предложи способ проверки.
